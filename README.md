# 条漫工作台（Comic Workbench）

本地单机的条漫生成管理工作台，集中管理：

1. **启动提示词**：维护每次生成任务使用的全局提示词，支持变量、命名画风列表（画风名称与描述均可作为变量，描述支持 AI 优化）、一键复制（自动替换画风变量）、AI 对话优化与恢复默认。
2. **故事管理**：故事原文、可选故事名、故事封面（图片上传；未上传时默认显示第 1 章封面，没有章节封面则用第一个镜头的成品图）、拆解画风，完整增删改查；原文支持「检测敏感词」：按全局词库精确扫描，逐词勾选、填写替换词、预览后应用，保留原文与替换审计；敏感词库默认带一套小红书 / 抖音商业合规词包（广告法极限词、虚假承诺、医疗功效、金融理财、教育培训、站外导流等），宽泛词默认停用，可在「设置 → 敏感词库」载入、编辑或导入完整词库；已拆解的故事改原文后会提示重新生成优化文与对照表。列表按创建时间倒序排列，最新创建的故事在最前，编辑旧故事不会改变位置；每条故事可一键复制拆解指令到 Claude Code。
3. **设计建议**：只需上传小红书截图或粘贴建议原文，即可维护成建议库（支持纯截图建议，标题自动生成）；分类（封面 / 漫画设计 / 标题 / 色彩 / 表情 / 文字 / 节奏 / 其他）、适用范围（全局 / 故事 / 章节）、标签、优先级与状态（待处理 / 已应用 / 已验证 / 不适用）都是可选的；每条建议可记录多次应用，保存目标、改动说明、改前 / 改后提示词或图片，详情里直接对比。建议由 Claude Code 提炼成结构化规则草案（正面提示词 / 负面约束 / 文字要求 / 审片标准 / 硬检查），支持全局 / 故事 / 章节 / 指定页面、规则版本、影响预览与回退；硬检查支持禁用词 / 必含词 / 字数 / 正则，渲染时返回结果；生成图或人工审片的核验结果可回填，规则卡片显示通过数，并可打开核验时间线；失败项可复制 `design-rule-rework` 返工指令，由 Claude Code 改提示词、重新 render 验证后再写回。规则还支持「仅本次」：选一张封面或正文页预览 before / after 后只改这一张，不激活规则；全局规则还可以预览 before / after 后写入正文 / 封面模板；写入会生成模板版本、自动停用规则，出问题可在模板历史回滚。失败核验还可以复制「自动流水线」指令，由 Claude Code 执行 render → 生图 → 审片 → 写核验；目前只支持章节封面，前端可选 1–3 张（默认 2 张），执行前需确认生图额度。网页只负责收录原始素材和审核激活，不提供手工写规则的入口，也不调用 DeepSeek。来自单篇笔记的建议默认先绑定具体故事 / 章节，先优化该章封面或内容；效果确认后点「推广到全局」，只复制 `design-rule-promote` 指令，由 Claude Code 把规则改成全局并同步技能、审片和检查脚本，不写模板。
4. **故事详情**：按「分镜对照 → 章节发布 → 分镜头脚本」组织拆解产物：
   - **分镜对照**：只读的「对照段 → 原文摘录」表，支持标记弃用段、查看优化文对照；
   - **章节发布**：一章 = 一篇小红书笔记，1 张封面 + 1–16 张正文 + 1 张引导卡（最多 18 张）；可规划章节、生成章节正文、生成封面 / 引导卡提示词并上传成品图；编辑章节时可先点「AI 生成封面文案（3 选 1）」：从本章最强钩子生成多组主标题/标红词/副标题，选定后连同匹配的画面提示词一起回填，保存后可直接生图或复制封面生成指令；也可以用「AI 优化画面提示词」继续调画面，顶部小字与标红词保持不变；章节卡片默认折叠，标题栏直接显示正文、总图、封面、引导卡进度，支持逐章展开或一键展开 / 收起；
   - **分镜成品图目录**：按章节存放为 `backend/uploads/pages/<故事ID>/chapter-<章节号>/page-<全局页码四位>.ext`；旧版平铺的 `page-<页码>.ext` 会在启动时自动迁移到章节目录。章节发布页还可一键导出「封面 → 正文 → 引导卡」顺序的 ZIP（ZIP 内按章节分文件夹），直接解压上传小红书即可；
   - **分镜头脚本**：顶部可直接打开「原文 / 优化文对比」（逐字差异 + AI 改动解读），下方按章节分组、章节与单页均可折叠展示分镜（故事内容、人物回顾、场景、动作、旁白/台词、景别、生图提示词），页码按章内页码显示，每页可单独复制提示词给 AI 生图 agent，也可勾选多页批量复制（按章节顺序、带序号和分隔线，适合一次生成多张图），还可编辑、删除；章节标题栏显示正文页数、已完成数和对应对照段范围；
   - **提示词历史**：章节封面与正文页的「提示词历史」可查看每次模板渲染的快照、命中的设计规则，并可恢复上一版提示词；恢复只改提示词，不自动重新生成图片；
   - **成品图历史**：章节封面 / 引导卡覆盖前自动归档旧图，可在「成品图历史」里查看并恢复任意一张；恢复前会把当前图也归档，恢复本身可再次回滚；
   - **生图回传接口**：生图 AI 可直接把成品图回传到正文页 / 章节封面 / 引导卡 / 角色资产图；支持图片 URL 或 base64，同页重复回传覆盖旧图；正文页支持一次最多 20 张的批量回传，逐页返回成功/失败，失败项可单独重试；角色资产图回传只更新目标角色的 `asset_filename`，返回角色卡与 `asset_url`。接口文档由 FastAPI 自动生成，启动后端后访问 `http://127.0.0.1:8123/docs`（机器可读版本：`/openapi.json`）；
  - **批量加别名**：章节发布 / 分镜头脚本页的「批量加别名」会原地给封面、正文页、引导卡底部居中写【别名】；首次处理前自动备份原图到 `backend/alias-backups/<故事ID>/`，可随时「恢复原图」。角色资产图不加；
   - **角色设定卡**：角色外形卡，角色名同时作为生图变量 `{{角色名}}`；可编辑、复制单个或全部变量绑定，也可用「AI 优化」对话调整外形（适合把在生图平台做过的形象微调同步回角色卡，流式生成、对比确认后直接写回卡片）。在生图平台确认形象后，可一键复制「更新角色卡」指令发给平台，再用「同步角色卡」粘贴平台回复整体写回：按角色名匹配更新、自动新增新角色，并由 AI 联动重写受影响分镜页的「人物回顾」。参考垫图仍由用户在外部生图 AI 中自行绑定；「复制全部变量」弹窗可勾选携带已有资产图的本地图片地址，复制结果会在末尾追加【角色垫图】分块。工作台不生成、不管理外部垫图；正文、章节封面、引导卡生成前必须先有角色卡，可在本页复制「角色卡指令」一次性拆完全部角色；
   - **角色资产图**：每张角色卡可上传或直接生成一张资产图（JPG / PNG / WebP，≤15MB），也可由外部生图 AI 通过 `POST /api/stories/{story_id}/breakdown/characters/{character_index}/asset-image/ingest` 用 URL 或 base64 回传；每张卡片有「复制回传指令」按钮，工具栏还有「复制批量回传指令」，可一次复制全部角色的批量请求 `POST /api/stories/{story_id}/breakdown/characters/asset-images/ingest`（最多 20 个角色，逐项返回成功/失败）。图片保存在 `backend/uploads/character-assets/<故事ID>/`，它既是本地存档，也是页面内封面生图的参考图；重复上传 / 回传 / 生成覆盖旧图，删除角色卡或故事时一并清理；
   - **生图前置提示词**：角色设定卡页顶部的可折叠输入框，默认包含「群像合照规则」与「垫图/角色参考图强制规则」。它保存在全局设置中、不与具体故事绑定，复制角色卡变量时会自动拼在最前面（开新会话时贴一次即可，分镜页的单页提示词不带），以后新建的故事同样生效；其中的 `{art_style_name}` 会替换为当前故事的画风名称，留空则不拼任何内容；
   - **知乎推广**：知乎原名标题直接使用故事名，无需重复录入；每篇故事维护原文 ID、候选别名与最终使用别名。别名可生成多个候选（6–8 个汉字，不复用故事名中的连续两字），在知乎注册确认后再标注最终使用哪一个；最终别名既可以从候选里选，也可以直接输入，保存后会自动加入候选列表。发文正文会自动以【最终别名】开头。
   - **发文配置**：按章节维护小红书标题与正文，可用 DeepSeek 生成本章文案；第 2 章起自动加入前情提要，最后一章结尾引导主页简介。标题限制 18 字以内，需用反差、悬念、利益点或强情绪制造点击欲。

> 「已发布」目前只是本地状态标记，不会自动调用小红书发布接口。

## 快速开始

### 环境要求

- Node.js 18+（本项目锁定 Vite 6，兼容 Node 18）
- [uv](https://docs.astral.sh/uv/)（Python 依赖管理）

### 一键启动（生产模式）

```bash
cd comic-workbench
./start.sh
```

首次运行会自动安装依赖、构建前端，然后访问：

```
http://127.0.0.1:8123
```

### 开发模式（前后端热更新）

```bash
cd comic-workbench
./dev.sh
```

- 前端：http://localhost:5173
- 后端：http://127.0.0.1:8123
- Vite 已将 `/api`、`/uploads` 代理到后端，无需配置 CORS。

## 配置 DeepSeek

有两种方式，**环境变量优先**：

1. 环境变量（推荐）：

   ```bash
   export DEEPSEEK_API_KEY=sk-xxxxxxxx
   ./start.sh
   ```

2. 页面配置：进入左侧菜单的「设置」页面，切到「DeepSeek 服务」标签填写并保存 Key。

说明：

- 页面保存的 Key 以明文存放在本机 SQLite 中（`data/workbench.db`），仅适合本地单机使用。
- 环境变量存在时，页面保存的 Key 不会生效，设置页会显示「环境变量生效」。
- 服务默认只监听 `127.0.0.1`，不要在没有鉴权的情况下改为公网监听。

## 配置生图服务（可选）

在「设置 → 生图服务」中填写接口地址、API Key、模型与尺寸，点「测试连接」确认 `/v1/models` 可用后保存。默认模型为 `gpt-image-2.5-sunburst`，默认尺寸 `1024x1536`，同步生成最长等待 600 秒。

使用顺序：

1. 先到故事详情的「角色设定卡」，给每个角色点「立即生图」，生成一张全身 / 七分身 / 半身三视角资产图；确认后写入角色资产图。
2. 再到「章节发布」，在章节封面旁点「立即生图」。后端会把提示词里的 `{{角色名}}` 映射为角色资产图参考图；缺资产图的角色会被拦下并提示先补图。
3. 接口返回后弹窗展示「左原图 / 右新图」，默认选新图；可选择使用新图、保留原图或重新生成。
4. 每次生成都会进入「历史」，可回选之前的图；「清除历史」只删除历史文件，不会删除当前正式图。

P0 只接角色资产图与章节封面；引导卡、分镜页后续接入。生图 Key 只保存在本机 SQLite，接口只返回脱敏值；也可用环境变量 `IMAGE_PROVIDER_API_KEY` 等覆盖。

## 提示词模板（正文 / 封面）

在「设置 → 提示词模板」里维护两份全局模板：

- `{art_style}` 自动注入故事画风原文，模板里不要复制画风文字；
- `{text_zone}`、`{page_number}`、`{cover_mode}`、`{negative_prompt}` 由后端渲染器生成；
- `{content}` 是 Claude 写的本页 / 本章【画面】描述；
- 保存前会校验必填占位符和未知占位符；「预览渲染结果」需要填一个已有画风的故事 ID；
- 「历史版本」可查看每次保存 / 恢复的模板快照，并恢复任意一版；恢复本身也留新版本，不删除历史；
- 模板只影响**新生成 / 重新渲染**的提示词，不会自动改写已有页面和封面。

Claude 技能在生成正文页和章节封面时调用 `POST /api/settings/prompt-templates/render`，接口会返回 `applied_rules`、`rule_checks` 和 `snapshot_id`；页面「立即生图」仍使用已经写回的 `image_prompt`。

## 使用流程

1. 在「启动提示词」中按需修改提示词，可使用 `{story_name}`、`{story_content}`、`{art_style}`、`{art_style_name}` 占位符；保存后刷新不会丢失。编辑器为左右双栏：左侧编辑原始内容，右侧实时预览画风变量替换后的完整提示词。点击右上角「复制提示词」可一键复制当前内容，粘贴到豆包等外部会话中使用。
   - 在「画风列表」中新增命名的画风（如「日系赛璐璐」「厚涂写实」）并选用；提示词里写 `{art_style}` 会替换为当前选用的画风描述，写 `{art_style_name}` 会替换为画风名称。未选用画风时若提示词包含画风变量，会阻止复制并提示先选用，避免把占位符原样粘贴给豆包。
   - 编辑画风时，描述旁的「AI 优化」可打开对话抽屉打磨画风描述（需配置 DeepSeek Key）；生成完成后先点「对比」查看原版与新版差异，确认后点「确认并应用」，再点「保存」。
   - 点击「AI 优化」可在右侧抽屉中与 AI 对话，说明修改诉求；AI 会基于编辑器中的当前内容流式给出完整新版。
   - AI 生成完成后，点击消息下方的「对比」查看字符级差异（GitHub 风格，删除 / 新增高亮）；确认无误后点「确认并应用」填入编辑器，再点「保存提示词」。应用本身不会自动保存。
2. 在「故事管理」中新建故事，填写原文、选择画风并上传封面（JPG / PNG / WebP，≤5MB）；**故事名可留空**，拆解时由 Claude 自动补填。
   - 画风下拉来自「启动提示词」页的画风列表，新建故事时默认选中当前选用项，每个故事都可以单独选择。未选择画风、或所选画风已被删除时，无法复制拆解指令。
   - 点击故事行内的「详情」（或点击故事名）进入故事详情页；点击「复制拆解指令」，把指令粘贴到本项目的 Claude Code 中。指令只携带故事 ID，Claude 会调用 `story-breakdown` 技能，并通过后端接口（`http://127.0.0.1:8123/api/stories/{id}`；后端未启动时回退直读 `data/workbench.db`）读取故事名、原文与画风。
   - 拆解开始前 Claude 会在第一行输出「故事名称：XXX」；若创建时未填名称，它会把拟定的名称自动回写数据库（已有名称不会被覆盖）。
   - 拆解是一次性交付，不等待参考垫图或人物合影：默认按「强节奏悬念」优化原文，不删情节、不合并信息点；第 1 页固定为「提问互动开场」的钩子封面（即小红书第一页），第 2 页起按优化文顺序拆页，并为每页标注页面作用（铺垫 / 冲突 / 反转 / 爆点 / 情绪高潮 / 收尾）。
   - 角色卡与全部分镜会一次性写回详情页，无需手动复制粘贴；每页生图提示词可在详情页一键复制。
   - 角色卡的 `name` 同时是生图变量名：每页提示词只写 `{{我}}`、`{{小八老师}}` 这样的变量，不重复粘贴整段外形描述。详情页可一键复制单个或全部变量绑定；你需要在外部生图 AI 中把变量绑定到对应角色参考图，再使用页面提示词。外部生图 AI 的参考垫图与人物合影仍由你管理；工作台内直接生图时，角色资产图会自动作为参考图。
   - 拆解会严格使用该故事选用的画风，所有分镜保持同一画风与同一套角色变量。
   - 详情页「分镜头脚本」顶部的「原文 / 优化文对比」：左侧原文、右侧优化文，字符级高亮改动；「改动解读」会调用 DeepSeek 逐条说明改了什么、属于钩子 / 悬念 / 信息差 / 爆点 / 节奏 / 保留等哪类调整，以及对读者的作用，适合不了解写作手法的用户快速理解优化思路（需配置 DeepSeek Key；两篇合计超过 45000 字时仅提供逐字对比）。
   - 若故事原文在拆解后被修改，或画风被更换，详情页会提示「原文已修改 / 画风已变更」，建议重新拆解。
   - 拆解规则维护在项目技能 `.claude/skills/story-breakdown/SKILL.md` 中，后续可直接修改优化；修改后在 Claude Code 中重新加载会话即可生效。

### 内容审阅 agent（Claude Code）

项目内置三个只读审阅 agent，定义在 `.claude/agents/`；它们只出建议，不写数据库，确认后由主会话修改：

| 中文名 | 文件 | 用途 |
|---|---|---|
| 分镜对照导演 | `mapping-director.md` | 拆 mapping，或审已有 mapping 的过载 / 过碎 / 不完整 |
| 旁白编辑 | `narration-editor.md` | 审主旁白、副旁白、标红词、台词与连读 |
| 审片导演 | `storyboard-director.md` | 审整章节奏、机位、连续性、图文一致 |
| 封面导演 | `cover-director.md` | 审章节封面的 3 秒抓眼、情绪强度、悬念、色彩与关键道具 |

调用示例（粘贴到 Claude Code）：

```text
用 mapping-director review 故事 5
用 narration-editor 检查故事 5 第 2 章
用 storyboard-director 审故事 5 第 2 章
```

新建或修改 agent 文件后，需要新开 Claude Code 会话才会加载。

从页面复制「本章脚本指令」时，指令已经包含生成后的自动审片：`script_check` → `narration-editor` → `storyboard-director`。粘贴一次即可，不需要再单独喊审片；审片只给问题清单，不会自动改页面。

### 章节封面质量门

编辑章节时先点「AI 生成封面文案（3 选 1）」：后端从本章 mapping 原文、前后章和已有发文标题里找最强钩子，生成 2–4 组封面文案；弹窗里选 1 组，主标题/标红词/副标题和对应的画面提示词会一起回填。第 1 章优先用故事核心关系 / 禁忌 / 代价，第 2 章起用上一章未解决的后果；有发文标题时，封面会和它讲同一个钩子，不再一个写辞职/办公室恋情、一个写无关的甜点。

选定并保存后，再复制「封面生成指令」，会生成 3 个不同钩子的画面变体，不会直接写回：

- A 道具特写：关键道具占前景，脸在中景
- B 真相揭示：X 光屏、手机、文件等揭示关键信息
- C 面对面强化：低机位近距离双人，表情张力最大化

再由 `cover-director` 按「3 秒抓眼、情绪强度、悬念、色彩对比、关键道具、文字可读性、画风一致性」评分，通过后由你选定再写回，最后跑 `cover_check.py`。封面统一走「原画风 + 封面专用冲击层」：保留原画风与低饱和彩铅，只加局部冲击层（夸张表情、动态张力、黑色震动线、放射线、锯齿符号、手绘涂鸦、粗线强调）；不整体提高对比度，也不压暗背景。冲击层有最低力度：至少 3 条粗黑集中手绘射线（有抖动感，不是细线或均匀速度线）、至少 2 处尺寸可辨的锯齿情绪漫符。背景与正文统一采用纸底简化标准：浅米色素描纸底，只保留 1–3 个关键环境的淡棕褐线轮廓，其余元素逐项排除，不压暗、不发黑。正文与封面的负面词已拆分：正文允许页码与对话气泡，封面禁止。

正文峰值页也可以使用冲击层，但要按评分卡判断：只在爆点 / 情绪高潮 / 反转页使用，单章最多 2 页、不得相邻、回忆页优先不用、铺垫 / 收尾 / 引导卡禁止。`storyboard-director` 会给出每页的 `none / light / strong` 建议，`script_check.py` 会检查页型、相邻与频率。

### 分镜对照审阅（页面）

分镜对照页的「审阅对照」用于处理 agent 生成的拆分提案：

- 提案写入 `mapping_reviews` 草稿，不会直接改 `mapping`；草稿绑定当前 mapping 哈希，mapping 改过后旧提案会自动拒绝。
- 低风险变更默认同意；中 / 高风险进入决策队列，可逐项选择「同意 / 保留 / 稍后」。
- 应用前会显示预计页数与影响；未决项按保留处理。
- 已有分镜页时不能应用，需要先清空分镜页。
- 已有章节时必须勾选确认清空：章节、章节文案会删除，章节封面 / 引导卡图片会移到 `backend/uploads/chapters-archive/` 备份。
- 应用后返回新的 mapping，页码由后端重排；归一化覆盖校验通过，严格逐行连续仅作为提示。

如果 `mapping-director` 输出的是完整候选 mapping，Claude Code 会先用转换脚本把它变成变更列表，再写入草稿：

```bash
cd backend
.venv/Scripts/python.exe ../.claude/skills/story-breakdown/proposal_to_changes.py \
  --story-id 5 \
  --proposal /path/to/proposal.json \
  --output /path/to/changes.json
```

然后 PUT `/api/stories/5/breakdown/mapping-review`，内容为 `changes.json`。

3. 在「故事详情 → 发文配置」中选择章节，维护该章的小红书标题与正文，可手动填写或点击「AI 生成本章文案」；AI 一次给出 3 个不同切入角度的方案（标注各自特点与推荐方案），选定后填入表单，不会自动保存，确认后点击「保存本章文案」。
   - 第 1 章不自动加前情提要；
   - 第 2 章起，正文第一段自动加入上一章的前情提要；
   - 非最后一章结尾埋下一章钩子；最后一章结尾弱引导「来我主页」，不写「主页简介 / 入口」这类直白导流词。

## 常见问题

- **Claude 读取不到故事**：确认后端已启动（`curl http://127.0.0.1:8123/api/health`），或确认项目根目录下存在 `data/workbench.db`；拆解指令中已写明这两种读取方式。
- **复制拆解指令时提示未选择画风 / 画风已失效**：编辑该故事重新选择画风；画风列表在「启动提示词」页维护。
- **生成文案提示「尚未配置 API Key」**：到「设置 → DeepSeek 配置」保存 Key，或设置 `DEEPSEEK_API_KEY` 后重启服务。
- **「AI 优化」按钮不可点击**：该功能复用 DeepSeek Key；按上一条配置后刷新页面即可。
- **复制提示词时提示先选用画风**：提示词中包含 `{art_style}` 或 `{art_style_name}` 变量，但「画风列表」里还没有选用的画风；选用一个画风（或删掉相关变量）后再复制。
- **DeepSeek 返回 401 / 余额不足**：在设置页更新有效 Key，或检查账户余额。
- **删除故事提示「已有发文记录」**：先删除该故事下的发文，再删除故事（避免误删已发布内容）。
- **端口 8123 被占用**：修改 `start.sh` / `dev.sh` 中的端口，并同步修改 `frontend/vite.config.ts` 的代理地址。
