# 故事优化与分镜拆解

## 使用方式

指令中通常只给出【故事 ID】。收到后先读取故事数据：

1. 优先调用本项目后端接口（默认 `http://127.0.0.1:8123`；若指令中给出了其他地址，以指令为准）：`curl -s <接口地址>/api/stories/<ID>`，从返回的 JSON 中读取 `name`（故事名）、`content`（故事原文）、`art_style_name`（画风名称）与 `art_style_content`（画风描述）。
2. 后端未启动时，直接读取项目根目录下的 SQLite：
   - `sqlite3 data/workbench.db "SELECT name, content, art_style_id FROM stories WHERE id = <ID>;"`
   - 若 `art_style_id` 非空，再执行 `sqlite3 data/workbench.db "SELECT value FROM app_settings WHERE key = 'art_styles';"`，把返回的 JSON 解析为数组，找到 `id` 相同的项，取 `name` 与 `content`。
3. 两种方式都读不到时，直接告诉用户读取失败的原因，不要向用户索要原文，也不要自行编造故事。
4. 后续所有分页生图都必须使用故事选用的这套画风。若 `art_style_id` 为空，或画风列表中找不到该 id（画风已被删除），先告诉用户并请其重新选择或提供画风描述，不要自行编造，也不要改用其他画风。

若用户直接给出了【故事名称】与【故事原文】（指令中没有 ID），直接使用粘贴的内容，并跳过【名称回写】与【结果写回】；此时若未提供画风，先向用户索取，不要自行编造。

## 执行流程

本流程是**一次性交付**：读故事 → 优化原文 → 拆角色卡 → 拆全部分镜 → 写回。不要停下来等待参考垫图、人物合影或分段确认。

1. 读取故事数据与画风，得到故事名、原文、画风名称/描述。回复第一行输出：`故事名称：XXX`；若原故事名为空，先根据原文拟定一个简洁名称，并按【名称回写】写回数据库（回写失败则提示用户手动补填）。
2. 按【故事优化规则】检查原文完整性。若原文疑似误截断，立即停止并提示用户补全；若用户已说明这是**刻意付费卡点、悬念留白或未完结章节**，保留原结尾，不补写、不扩写。
3. 按【优化方案】优化原文，默认使用 **B. 强节奏悬念**；只有用户明确要求比较方案时，才先给出 2～3 个方案供选择。优化文用于后续角色卡与分镜，不再单独等待确认。
4. 按【角色设定与变量】拆出全部角色卡。角色卡中的 `name` 同时是生图变量名；外形描述完整写入角色卡，供用户在外部生图 AI 中绑定参考图。
5. 按【首图钩子规则】与【分镜拆页规则】一次性拆完全部分镜。每页的 `image_prompt` 用 `{{角色名}}` 变量引用角色外形，不展开成长段外形描述；不需要等待参考垫图，也不需要生成人物合影提示词。
6. 按【结果写回】一次性写回：PATCH 优化文与角色卡 → 清空旧分镜页 → 逐页 PUT。写回与聊天输出可以并行，不要因为输出分段而中断写回。
7. 严格按【每页输出格式】完整输出每一页的全部条目，严禁缺项、省略、删减或简化。受单次输出长度限制时可以分段输出，但不要停下来等待确认，也不要只输出摘要。
8. 只输出文字脚本与生图提示词，不要实际生成图片，不要生成或管理参考垫图。

【名称回写】
仅当故事原本没有名称、且数据是通过【故事 ID】从数据库读取时执行：
1. GET `<接口地址>/api/stories/<ID>` 取得完整记录（默认 `http://127.0.0.1:8123`，以指令中给出的地址为准）；
2. 把 `name` 改为拟定的名称，`content` 与 `cover_filename` 原样保留，再 PUT 回同一地址；
3. 建议用 Python 构造请求，避免长文本转义出错：

```bash
python3 - <<'PY'
import json, urllib.request

url = "http://127.0.0.1:8123/api/stories/<ID>"
story = json.load(urllib.request.urlopen(url))
story["name"] = "拟定名称"
req = urllib.request.Request(
    url,
    data=json.dumps(story, ensure_ascii=False).encode("utf-8"),
    headers={"Content-Type": "application/json"},
    method="PUT",
)
urllib.request.urlopen(req)
PY
```

4. 故事原本已有名称时不要改写；回写失败不影响后续拆解，提示用户手动补填即可。

【故事优化规则】
我们做的是短文，**不做故事简化**。优化只服务于阅读节奏与画面表现，不得改变故事本身：
1. **不得删情节、合并信息点、跳过细节**，也不得把心理活动整体删掉改成一句旁白。原文有的内容，优化后必须仍然可追溯。
2. 只做语言润色与段落节奏调整：顺句、去口头禅式重复、调整句子长短与分段，让读者更容易一口气读下去。
3. 保留原文的第一人称口吻与幽默、自嘲、克制或尖锐的语气；不要把叙述改成书面腔或第三人称。
4. 不改变事实、人物关系、时间线、因果与结局；不新增原文没有的情节、对话或心理活动。
5. 原文完整性判断：
   - 若句子戛然而止、上下文明显断裂，且用户没有说明原因，先告诉用户「原文疑似不完整，缺少 X 部分」并停止，等补全后再继续。
   - 若用户已说明结尾是**付费卡点、刻意留白、未完结**（例如“后面的需要付费”“故事就到这里”），视为有效结尾，保留断点，不补写后续。
6. 优化后的文章是后续角色卡与分镜的唯一依据，人物、场景、动作必须与优化文一致。
7. 完整优化文长度控制在原文的 0.9～1.2 倍，不得为了「更好看」而扩写成新故事。

【优化方案】
默认使用 **B. 强节奏悬念**，直接输出完整优化文，不要停下来等用户选择。只有用户明确说“给我几个方案”时，才先给出以下选项：
- **A. 保留原味**：只做轻润色与分段，最大限度保留原文的语气与节奏。
- **B. 强节奏悬念**：短句为主、信息前置，把反转与冲突尽量提前，适合快速抓人。
- **C. 情绪冲突**：强化对话与人物反应，把尴尬、冲突、反转的情绪张力写足。

【角色设定与变量】
  根据优化文拆出全部人物设定文字卡：发型、长相、年龄感、服装、配饰、体态，每个角色一段描述。
  女性角色统一基准：成年女性，7头身写实比例，鹅蛋脸，五官柔和精致，身形具有自然柔和的女性曲线，胸廓线条柔和，胸部轮廓清晰自然，腰臀过渡柔和，肩背线条柔和不硬朗，体态舒展、不扁平、不男性化，比例协调真实，成熟轻性感、克制写实，不做夸张性感化处理。
  体态用温和、精准的写实描述，不要堆“丰满、性感、火辣”等夸张词；“扁平、平胸、男性肩宽、雌雄难辨”这类是负面约束，只能写进【负面提示词】，严禁混入画风的正面描述，否则会反向生成错误体型。
  需要轻性感时，用修身剪裁、柔和微开领口、浅锁骨小幅露肤等克制处理，禁止大面积露肤；【负面提示词】必须包含“过度暴露、低俗、色情”。

### 变量约定
1. 角色卡的 `name` 就是生图变量名，变量写法为 `{{角色名}}`，例如 `{{我}}`、`{{小八老师}}`、`{{朋友}}`。
2. 每页 `image_prompt` 中，凡是涉及角色外形、五官、发型、服装、配饰、身高体态的内容，一律只写变量，例如：
   - 正确：`人物严格遵循 {{我}}、{{小八老师}} 的角色设定与参考图。`
   - 错误：在提示词里重复粘贴“28岁、黑色短发、方圆脸……”等整段外形描述。
3. 完整外形描述保留在角色卡和每页 `character_review` 中；用户会在外部生图 AI 中把 `{{角色名}}` 绑定到对应角色参考图或角色设定。
4. 同一故事内角色卡姓名必须唯一且全程一致；分镜 `characters` 数组、`character_review`、`image_prompt` 中的变量名必须与角色卡姓名完全一致。
5. 如果某页出现了角色卡中没有的人物，先补充角色卡，再写该页；禁止使用未登记的角色变量。
6. 工作台不生成、不保存、不管理参考垫图，也不生成人物合影提示词。参考图由用户在外部生图 AI 中自行准备和绑定；不要停下来等待用户上传垫图。

【首图钩子规则】
第 1 页就是小红书作品的第一页，决定读者是否点进来，固定采用「提问互动开场」：
1. **主要旁白**：直接向读者发问，一句话、短促有力，制造代入感或认知缺口。
2. **副旁白**：交代情境（谁、在哪、发生了什么），让读者知道这个问题从何而来。
3. **信息差/悬念**：主要旁白或副旁白结尾要抛出反常信息、反转暗示或利益冲突，让读者想点进来看后续。
4. **画面**：聚焦核心人物或关键道具，通常用特写或中景；表情、动作、构图要为「问题」服务，而不是平铺直叙。
5. 第 1 页可以不按原文顺序起手，但必须与后文事实一致，不得编造原文没有的信息。
6. 第 2 页起进入正文，按优化文的自然顺序叙事；不要与第 1 页重复同一动作、同一句台词或同一画面。

【分镜拆页规则】
因为是整幅单画面不是分格漫画，一张图里塞不下太多内容，按以下规则拆页：
1. 每页主要旁白固定仅 1 句（情绪/钩子）；副旁白为本页优化后的故事内容；对话气泡不超过两个，单句台词不超过 15 个字。
2. 每页只表现一个动作或一个情绪点，不要一页塞多个情节。
3. 一段对话或一个情节内容多就拆成多页，换不同机位和景别来表现：全景交代环境、中景交代人物互动，特写交代表情和关键道具。
4. 情绪高潮页用人物面部特写，转折页用全景，动作页用中景。
5. 为每页标注 `page_role`（页面作用），只能取：`钩子封面`（仅第 1 页）、`铺垫`、`冲突`、`反转`、`爆点`、`情绪高潮`、`收尾`。每页只选本页最主要的功能，不要全部笼统写「铺垫」：交代背景/人物=铺垫，矛盾开始激化=冲突，真相或人物态度翻转=反转，情绪或冲突最炸的一句=爆点，哭泣/争吵等情绪顶点=情绪高潮，收束结尾或引导互动=收尾。第 1 页固定为 `钩子封面`。
6. 拆页时按故事自然节奏走，不要为了凑页数硬拆，也不要为了少出图把内容挤在一页里。
7. 称谓规则：第一人称主角统一用「我」，其他角色直呼姓名，禁用他/她代词。
8. 回忆页在副旁白开头标注「（回忆）」并交代时间或起因，同时把 `is_flashback` 写为 `true`。
9. 每页的人物外形、服装、配饰、体态必须与角色卡一致；换页不换人设，除非剧情明确要求换装。

【结果写回】
仅当指令提供了【故事 ID】时执行。接口地址默认 `http://127.0.0.1:8123`，以指令中给出的地址为准；所有请求体使用 UTF-8 编码的 JSON。

写回前先 GET `/api/stories/<ID>/breakdown` 确认当前状态：
- 返回 `null` 表示还没有拆解结果，本次 PATCH 会创建；
- 创建拆解要求故事有有效画风，否则接口返回 `422 ART_STYLE_REQUIRED`，此时告知用户先去故事列表重新选择画风并停止写回；
- 若已有旧结果，PATCH 会覆盖对应字段；开始写分镜前必须清空旧分镜页。

阶段 1：优化文与角色卡生成后，写入头部信息：

```json
PATCH /api/stories/<ID>/breakdown
{
  "optimized_content": "优化后的完整文章",
  "characters": [
    {"name": "我", "role": "主角", "appearance": "发型、长相、年龄感、服装、配饰、体态"}
  ]
}
```

说明：角色卡的 `name` 将作为 `{{角色名}}` 变量名，必须是稳定、唯一、可直接用于提示词的称呼。不要再写 `group_photo_prompt`。

阶段 2：清空旧分镜页，再逐页写入新分镜：

```text
DELETE /api/stories/<ID>/breakdown/pages
PUT    /api/stories/<ID>/breakdown/pages/<页码>
```

单页请求体字段与【每页输出格式】的对应关系：

| 请求字段 | 内容 |
|---|---|
| `is_flashback` | 是否回忆页，布尔值 |
| `page_role` | 页面作用：钩子封面 / 铺垫 / 冲突 / 反转 / 爆点 / 情绪高潮 / 收尾 |
| `story_content` | 本页故事内容 |
| `characters` | 出场人物姓名数组 |
| `character_review` | 人物设定回顾，写完整外形描述 |
| `scene` | 场景描述 |
| `action_state` | 动作与状态 |
| `change_note` | 变化说明 |
| `narration_main` | 主要旁白 |
| `narration_highlight` | 标红关键词 |
| `narration_sub` | 副旁白 |
| `dialogues` | 对话气泡数组，最多 2 条，每条不超过 100 字 |
| `shot_type` | `全景` / `中景` / `特写` |
| `image_prompt` | 完整生图提示词，角色外形用 `{{角色名}}` 变量 |

字段上限：页码 1～200；角色卡最多 20 张；`narration_main` 不超过 200 字；`narration_highlight` 不超过 100 字；`scene` / `action_state` / `change_note` / `narration_sub` 等长文本不超过 4000 字；`image_prompt` 不超过 8000 字。超出会导致 `422`，写回前需自行压缩，但不得缺项。

建议用一个 Python 脚本统一调用，避免长文本转义问题：

```bash
python3 - <<'PY'

BASE = "http://127.0.0.1:8123"
STORY_ID = 2

def call(method, path, payload=None):

        data=data,
        headers={"Content-Type": "application/json"},
        method=method,
    )
    with urllib.request.urlopen(req) as resp:
        body = resp.read()
        return json.loads(body) if body else None

# 阶段 1：优化文 + 角色卡

})

# 阶段 2：清空旧页，再逐页写入
call("DELETE", f"/api/stories/{STORY_ID}/breakdown/pages")
call("PUT", f"/api/stories/{STORY_ID}/breakdown/pages/1", {
    "is_flashback": False,
    "page_role": "钩子封面",
    "story_content": "……",
    "characters": ["我", "小八老师"],
    "character_review": "{{我}}：……；{{小八老师}}：……",
    "scene": "……",
    "action_state": "……",
    "change_note": "……",
    "narration_main": "……",
    "narration_highlight": "……",
    "narration_sub": "……",
    "dialogues": ["……"],
    "shot_type": "特写",
    "image_prompt": "……人物严格遵循 {{我}}、{{小八老师}} 的角色设定与参考图……",
})
PY
```

写回失败处理：
1. 网络错误或服务端 5xx 时重试 1 次；
2. 仍失败必须明确告诉用户「结果仅在对话中，未能写入详情页」，并保留对话中的完整输出，不要静默忽略；
3. `422` 校验失败不要盲目重试，按返回的字段错误修正后再写一次，仍失败则告知用户具体字段。

【每页输出格式】
【重要强制约束：每页生图前，必须完整输出下面全部条目，严禁缺项、省略、删减任何一条内容，不允许简化输出，不允许跳过任何模块。】
生图前先报告项目进度：当前第X页/共Y页，正在生成第X页
1. 本页故事内容：这一页讲什么事，标注【是否回忆页】。
1.5 本页页面作用（`page_role`）：钩子封面 / 铺垫 / 冲突 / 反转 / 爆点 / 情绪高潮 / 收尾，取本页最主要的一个。
2. 本页出场人物：列出这一页出现的角色。
3. 人物设定回顾：每个出场角色原本的发型、长相、年龄感、服装、配饰、身高比例；以角色卡为准，建议按 `{{角色名}}：外形描述` 的格式书写；女性角色：鹅蛋脸，五官柔和，7头身写实比例，自然柔和曲线，肩背柔和不硬朗，胸部轮廓清晰自然，成熟轻性感有分寸，不扁平、不男性化。
4. 本页场景描述：明确本页所处环境、空间、固定道具，锁定场景，防止场景错乱。
5. 本页人物动作与状态：每个出场人物在画面里具体在干嘛，站着还是坐着、面朝哪个方向、手在做什么、视线看向哪里、什么表情、和谁互动，人物姿态端庄自然，无挑逗动作；五官、身材、穿搭不偏离角色卡。
6. 本页变化说明：这一页里人物做了什么动作、什么情绪；除非剧情要求换装，否则服装造型、体态比例不能改动。
7. 旁白和台词：
