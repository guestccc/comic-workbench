# 故事优化与分镜拆解

## 使用方式

指令中通常只给出【故事 ID】。收到后先读取故事数据：

1. 优先调用本项目后端接口（默认 `http://127.0.0.1:8123`；若指令中给出了其他地址，以指令为准）：`curl -s <接口地址>/api/stories/<ID>`，从返回的 JSON 中读取 `name`（故事名）、`content`（故事原文）、`art_style_name`（画风名称）与 `art_style_content`（画风描述）。
2. 后端未启动时，直接读取项目根目录下的 SQLite：
   - `sqlite3 data/workbench.db "SELECT name, content, art_style_id FROM stories WHERE id = <ID>;"`
   - 若 `art_style_id` 非空，再执行 `sqlite3 data/workbench.db "SELECT value FROM app_settings WHERE key = 'art_styles';"`，把返回的 JSON 解析为数组，找到 `id` 相同的项，取 `name` 与 `content`。
3. 两种方式都读不到时，直接告诉用户读取失败的原因，不要向用户索要原文，也不要自行编造故事。
4. 后续所有分页生图都必须使用故事选用的这套画风。若 `art_style_id` 为空，或画风列表中找不到该 id（画风已被删除），先告诉用户并请其重新选择或提供画风描述，不要自行编造，也不要改用其他画风。

若用户直接给出了【故事名称】与【故事原文】（指令中没有 ID），直接使用粘贴的内容，并跳过【名称回写】与【结果写回】；此时若未提供画风，先向用户索取，不要自行编造。

## 分步流程（推荐）

指令里写明「分镜对照」「分镜头脚本」「章节规划」「章节正文脚本」「章节封面」「章节引导卡」时，严格按本节执行，不要走下面的【执行流程】一次性交付。

### 一、分镜对照模式

目标：只写 `mapping`，不写 `pages`，不生成分镜脚本。

1. 读取故事、画风与现有 breakdown（`optimized_content` / `characters` / `mapping` / `pages`）。
2. **优化文**：`optimized_content` 为空时，按【优化方案】优化原文并 PATCH 写回；已有优化文时直接使用，**不要重新优化、不要覆盖**。
3. **切镜头段落**：
   - 一个镜头能放的内容很少：一个动作、一个情绪、一句关键台词或一个小信息点 = 一个镜头段落；
   - 一个自然段太长，就按句子/动作拆成多个镜头段落；短段落不合并；
   - 每个镜头段落 = 一页，页码从 1 连续编号；
   - **第 1 页就是原文第一个镜头段落，不生成钩子页**；
   - **严格按原文顺序**：不重排、不去重、不跳段、不合并跨段事件；原文开头预叙、后文重复讲同一件事时，两处都按原文位置各出页；
   - 单独成行的章节编号（1/2/3…）不是镜头内容，**不要单独成页**，并入相邻页的 `source_text`（通常在段首）。
4. 每页写一条 mapping：
   - `page_number`：页码；
   - `source_text`：该页对应的优化文连续摘录，**不改写**；所有页按顺序拼接应覆盖整篇优化文，不重叠、不遗漏；
   - `summary`：一句话简述这一页讲什么；
   - `paragraph`：原文段号（如「第3段」）；
   - `part`：拆分序号（如「1/2」），没有拆分可留空。
5. PATCH `/api/stories/<ID>/breakdown` 写入 `mapping`。**不要写 pages，不要 DELETE pages，不要 PATCH characters。** 如果旧 mapping 里有 `excluded=true` 的弃用段，重写时尽量保留同一段的弃用标记；无法对应时先问用户。
6. 运行 `.claude/skills/story-breakdown/mapping_check.py --story-id <ID>`：去掉标点和空白后，mapping 按页码拼接必须与 optimized_content 完全一致；不一致先修 mapping。
7. 输出完整对照表（页码 / 原文位置 / 原文摘录 / 本页简述），然后停下来等用户确认。

`mapping` 格式：

```json
[
  {"page_number": 1, "source_text": "祝卿冒领了我的情书，和校草谈了恋爱。", "summary": "祝卿冒领情书", "paragraph": "第1段", "part": "1/1", "excluded": false}
]
```

`excluded=true` 表示这一段保留在对照表里维持全文覆盖，但永久弃用，不再分入任何章节、也不生成正文页。

自检：页码连续；`source_text` 按顺序拼接能覆盖全文；没有钩子页、没有重排、没有跨段合并。

### 二、分镜头脚本模式

目标：读取已确认的 `mapping`，按用户选中的对照段生成分镜页。

**两个页码必须分开：**

- `mapping[].page_number`：**对照段号**，按优化文顺序编号，只用于选段和追溯原文；
- `pages[].page_number`：**脚本页码 / 成片页序**，必须从 1 连续编号；
- 每个脚本页写入 `mapping_page_number`，记录它来自哪个对照段。

1. 读取 breakdown。`mapping` 为空时停止，告诉用户先执行「分镜对照」；画风为空或失效时停止。指令中的“第 1、2、5 页”如果没有特别说明，指的是 **mapping 的对照段号**；只处理这些段，其他段跳过。
2. `characters` 为空时，按【角色设定与变量】拆出角色卡并 PATCH 写回；已有角色卡则沿用，不要覆盖。
3. **计算脚本页码**：
   - 当前 `pages` 为空：把选中的对照段按 mapping 顺序排好，依次生成脚本第 1…N 页。跳过的对照段不占号。例如选中对照第 1–6、8–18 段，则对照第 8 段 → 脚本第 7 页，对照第 18 段 → 脚本第 17 页。
   - 当前 `pages` 非空：用每页的 `mapping_page_number` 找到选中对照段对应的现有脚本页，只覆盖这些页，**脚本页码保持不变**；未选中的脚本页保留。
   - 如果 `pages` 非空，但某个选中的对照段没有对应脚本页：**不要插入、不要重排、不要追加到末尾**，立即停止并告诉用户“请先清空分镜脚本，再按新选择重新生成”。
   - 如果用户要新增或删除对照段（例如找回之前跳过的第 7 段）：同样要求先清空 `pages`，再重新生成。
4. **只按 mapping 逐页生成**：每页对应的 `source_text` 以 mapping 为准；不重新拆页、不重排、不修改 mapping。
5. 每页字段：
   - `mapping_page_number`：本页来源的对照段号；
   - `story_content`：先写清楚本页故事内容，必须包含「谁 + 在哪 + 做了什么 + 结果/情绪」；它是副旁白的底稿；
   - `narration_sub`：以 `story_content` 为底稿写成画面文字，用主角第一人称，**< 50 个汉字（标点不计）**；允许 1–2 行（用换行符分行）；每页必须能独立看懂，保留姓名、时间、地点、关键动作和结果/情绪；需要承接上一页时可加半句，但不能只写半句；
   - `narration_main`：本页内容的提炼标题，**< 15 个汉字（标点不计）**，要吸引人，不独立发挥；
   - `narration_highlight`：从主旁白或副旁白中选连续片段；没有就留空；
   - 其余字段：`characters` / `character_review` / `scene` / `action_state` / `change_note` / `dialogues` / `shot_type` / `camera_angle` / `image_prompt`，按后文规则填写；
   - `image_prompt` 按 7 类分行，角色外形用 `{{角色名}}` 变量，【文字区】用新模板；
   - **不生成钩子页**，脚本第 1 页是本次选中段中的第一段，不一定是 mapping 第 1 段。
6. 写回前自检：`pages` 按 `page_number` 从 1 连续、无空号；每页都有 `mapping_page_number`，不重复且存在于 mapping；本次选中的对照段都有对应脚本页；`narration_main` < 15 个汉字、`narration_sub` < 50 个汉字（标点不计），且不超过 2 行；字段没有空缺。运行 `.claude/skills/story-breakdown/script_check.py --story-id <ID> --mapping-pages 1,2,5`（分镜尚未写回时用 `--input` 传入本地 JSON），未通过不得写回。
7. 写回：
   - `pages` 为空、从空白生成：先 DELETE `/pages` 清空旧页，再按脚本页码逐页 PUT；
   - 已有 `pages`、局部重新生成：只对本次目标脚本页 DELETE `/pages/<脚本页码>`，再 PUT 同一页码；未选中的页保持原样；
   - 每个 PUT 请求体都要带 `mapping_page_number`；
   - **不要 PATCH optimized_content / mapping；已有角色卡不要覆盖。**
8. 完整输出每页全部条目，最后报告实际写入页数、每页「来源对照段 → 脚本页码」与跳过的对照段。

### 三、章节规划模式

目标：把连续的 `mapping` 分成若干章（一章 = 一篇小红书笔记），只写 `chapters`，不写 `pages`。

1. 读取 `mapping`、`pages`、`characters`、`optimized_content` 与画风。
2. **每章结构**：1 张章节封面 + 1..16 张正文 + 1 张引导卡，总图必须 ≤18。正文超过 16 页必须继续拆章。
3. **切章规则**：
   - 按剧情钩子切，不按 16 页硬切；每章正文尽量 14–16 页，结尾停在悬念、反转或冲突升级处；少于 14 页可以接受。
   - 所有 `excluded=false` 的 mapping 段必须按对照表顺序分配到章节，不重不漏；`excluded=true` 的段跳过。
   - `chapter_number` 从 1 连续编号；`title` 简洁有吸引力，≤50 字。
4. **cover 文字**：
   - `label`：`第X章 · 章节标题`；
   - `narration_main`：主旁白，<15 个汉字，必须是钩子；
   - `narration_highlight`：从主旁白里选连续片段作为标红词；
   - `narration_sub`：副旁白，<35 个汉字；第 1 章写 premise（前情/设定），第 2 章起写上一章的前情提要；
   - `image_prompt` 先留空。
5. **guide 文字**：
   - 非最后一章：`text="关注我，看更多重生爽文"`，`sub_text="下一章：<下一章钩子>"`；
   - 最后一章：`text="想看后续？来我主页"`，`sub_text="关注我，不迷路"`；
   - `image_prompt` 先留空。
6. PATCH `/api/stories/<ID>/breakdown` 写入完整 `chapters` 数组；**不要写 pages，不要 PATCH mapping / characters / optimized_content**。
7. 运行 `.claude/skills/story-breakdown/chapter_check.py --story-id <ID>`：章节覆盖、每章 18 张上限、封面文字字数未通过时先修。
8. 输出章节规划表（章节 / 对照段范围 / 正文页数 / 总图数 / 结尾钩子），停下来等用户确认。

`chapters` 格式：

```json
[
  {
    "chapter_number": 1,
    "title": "如果一切能重来",
    "mapping_page_numbers": [1, 2, 3],
    "cover": {
      "label": "第1章 · 如果一切能重来",
      "narration_main": "这一次，她只想回家",
      "narration_highlight": "回家",
      "narration_sub": "重来一世，她只想回家见奶奶。",
      "image_prompt": ""
    },
    "guide": {
      "text": "关注我，看更多重生爽文",
      "sub_text": "下一章：祝卿当场摔杯",
      "image_prompt": ""
    }
  }
]
```

### 四、章节正文脚本模式

目标：只生成某一章的正文页，不改章节规划和其他章节。

**三种页码：**

- `mapping.page_number`：对照段号；
- `pages.page_number`：全局脚本页码，由前面章节的正文页数累加得到；
- `pages.chapter_page_number`：章内页码，图片里显示的「第X页」。

1. 读取 `chapters`，找到目标章；目标章的 `mapping_page_numbers` 就是正文页顺序。
2. **全局页码** = 前面所有章节的正文页数之和 + 本章章内页码。例如第 1 章 16 页，则第 2 章第 1 页的全局页码是 17。
3. **默认只补缺失页**：已有页面按 `mapping_page_number` / `chapter_number` / `chapter_page_number` 保留，不要覆盖；只有指令明确要求「整章重做」时才覆盖全部本章页。
4. 每页字段：
   - `chapter_number`、`chapter_page_number`、`mapping_page_number` 必须写入；
   - 其余字段与【二、分镜头脚本模式】相同；
   - `image_prompt` 里的【页码】写**章内页码**，不要写全局页码；**严禁**写 `mapping_page_number`（对照段号）或全局 `page_number`（例如第 2 章第 1 页应写「第1页」，不能写「第17页」或「第18页」）。
5. 写回：
   - 只对本次目标全局页码 DELETE `/pages/<全局页码>`，再 PUT 同一全局页码；
   - **不要 DELETE `/pages`**，不要动其他章节；
   - 封面和引导卡不在 `pages` 中，不要生成。
6. 写回前运行 `.claude/skills/story-breakdown/script_check.py --story-id <ID> --chapter <N>`；未通过不得写回。
7. 输出本次写入页数、每页「第X章第Y页 → 全局第Z页 → 对照第N段」、保留页和字数自检。

### 五、章节封面 / 引导卡模式

目标：只生成某一章的封面或引导卡生图提示词，写回 `chapters[].cover.image_prompt` / `guide.image_prompt`。

1. 封面 / 引导卡不是正文页，不写入 `pages`，不显示页码，不参与正文覆盖检查。
2. 画风、角色、构图必须与故事正文一致；主角出现在画面中，角色外形用 `{{角色名}}` 变量引用。
3. 封面文字：
   - 顶部小字 `label`；
   - 主旁白大字，标红词必须内嵌在原句中，绝对禁止单独另起一行；
   - 副旁白小字（第 2 章起是前情提要）；
   - 除这些文字外不得出现其他文字、页码、水印、logo。
4. 引导卡文字：
   - 主文案一行，副文案一行；
   - 主文案中包含「关注我」时，仅「关注我」3 个字必须用红色手写加粗，必须内嵌在主文案整句中，绝对禁止单独另起一行或做成第三块文字区；主文案不含「关注我」时全部文字保持黑色，不要把副文案中的「关注我」自动标红；
   - 不显示页码，不出现额外文字。
5. 生图提示词按【画风】【画面】【角色一致性】【画面形式】【文字区】【负面提示词】分类，**不要写【页码】**。
6. 写回时读取完整 `chapters`，只替换目标章节的 `cover.image_prompt` 或 `guide.image_prompt`，其他章节与字段原样保留；PATCH 完整 `chapters` 数组。
7. 不要修改 `mapping`、`pages`、`characters`、`optimized_content`。

### 分步流程的优先级

- 【首图钩子规则】**不适用**：不生成钩子页；以后需要钩子镜头时，用独立的钩子功能。
- 【正文覆盖与去重规则】里的「预叙只拆一次」**不适用**：两步流程严格按原文位置，重复的预叙/回忆也各出页。
- 内容顺序与每页来源以 mapping 为准，不再自由拆页；脚本页码按“本次选中的对照段”连续编号，mapping 页码只是来源编号。

## 执行流程（旧一次性流程）

> 仅当指令没有写明「分镜对照」或「分镜头脚本」时使用；新流程请用上面的两步流程。

本流程是**一次性交付**：读故事 → 优化原文 → 拆角色卡 → 切 beat → 拆全部分镜 → 覆盖自检 → 写回。不要停下来等待参考垫图、人物合影或分段确认。

1. 读取故事数据与画风，得到故事名、原文、画风名称/描述。回复第一行输出：`故事名称：XXX`；若原故事名为空，先根据原文拟定一个简洁名称，并按【名称回写】写回数据库（回写失败则提示用户手动补填）。
2. 按【故事优化规则】检查原文完整性。若原文疑似误截断，立即停止并提示用户补全；若用户已说明这是**刻意付费卡点、悬念留白或未完结章节**，保留原结尾，不补写、不扩写。
3. 按【优化方案】优化原文，默认使用 **B. 强节奏悬念**；只有用户明确要求比较方案时，才先给出 2～3 个方案供选择。优化文用于后续角色卡与分镜，不再单独等待确认。
4. 按【角色设定与变量】拆出全部角色卡。角色卡中的 `name` 同时是生图变量名；外形描述完整写入角色卡，供用户在外部生图 AI 中绑定参考图。
5. 按【正文覆盖与去重规则】把优化文切成 beat 并编号，确认每个 beat 都有落页位置；第 1 页钩子不计入正文覆盖。
6. 按【首图钩子规则】与【分镜拆页规则】一次性拆完全部分镜。每页的 `image_prompt` 用 `{{角色名}}` 变量引用角色外形，不展开成长段外形描述；不需要等待参考垫图，也不需要生成人物合影提示词。
7. 按【正文覆盖与去重规则】做覆盖自检：输出「beat → 页码」覆盖表，运行 `coverage_check.py` 检查未落页句子与疑似重复页；有缺失先补页，有重复先删页，不通过不得写回。
8. 按【结果写回】一次性写回：PATCH 优化文与角色卡 → 清空旧分镜页 → 逐页 PUT。写回与聊天输出可以并行，但覆盖自检必须先通过；不要因为输出分段而中断写回。
9. 严格按【每页输出格式】完整输出每一页的全部条目，严禁缺项、省略、删减或简化。受单次输出长度限制时可以分段输出，但不要停下来等待确认，也不要只输出摘要。
10. 只输出文字脚本与生图提示词，不要实际生成图片，不要生成或管理参考垫图。

**只重拆分镜模式**：若指令明确要求「只重拆分镜 / 不重新优化」，跳过第 2、3 步，直接读取现有 `/api/stories/<ID>/breakdown` 的 `optimized_content` 与 `characters` 作为唯一依据，沿用现有优化文与角色卡，只重新切 beat、拆页、自检和写回分镜页；不要 PATCH 优化文与角色卡。

【名称回写】
仅当故事原本没有名称、且数据是通过【故事 ID】从数据库读取时执行：
1. GET `<接口地址>/api/stories/<ID>` 取得完整记录（默认 `http://127.0.0.1:8123`，以指令中给出的地址为准）；
2. 把 `name` 改为拟定的名称，`content` 与 `cover_filename` 原样保留，再 PUT 回同一地址；
3. 建议用 Python 构造请求，避免长文本转义出错：

```bash
python3 - <<'PY'
import json, urllib.request

url = "http://127.0.0.1:8123/api/stories/<ID>"
story = json.load(urllib.request.urlopen(url))
story["name"] = "拟定名称"
req = urllib.request.Request(
    url,
    data=json.dumps(story, ensure_ascii=False).encode("utf-8"),
    headers={"Content-Type": "application/json"},
    method="PUT",
)
urllib.request.urlopen(req)
PY
```

4. 故事原本已有名称时不要改写；回写失败不影响后续拆解，提示用户手动补填即可。

【故事优化规则】
我们做的是短文，**不做故事简化**。优化只服务于阅读节奏与画面表现，不得改变故事本身：
1. **不得删情节、合并信息点、跳过细节**，也不得把心理活动整体删掉改成一句旁白。原文有的内容，优化后必须仍然可追溯。
2. 只做语言润色与段落节奏调整：顺句、去口头禅式重复、调整句子长短与分段，让读者更容易一口气读下去。
3. 保留原文的第一人称口吻与幽默、自嘲、克制或尖锐的语气；不要把叙述改成书面腔或第三人称。
4. 不改变事实、人物关系、时间线、因果与结局；不新增原文没有的情节、对话或心理活动。
5. 原文完整性判断：
   - 若句子戛然而止、上下文明显断裂，且用户没有说明原因，先告诉用户「原文疑似不完整，缺少 X 部分」并停止，等补全后再继续。
   - 若用户已说明结尾是**付费卡点、刻意留白、未完结**（例如“后面的需要付费”“故事就到这里”），视为有效结尾，保留断点，不补写后续。
6. 优化后的文章是后续角色卡与分镜的唯一依据，人物、场景、动作必须与优化文一致。
7. 完整优化文长度控制在原文的 0.9～1.2 倍，不得为了「更好看」而扩写成新故事。

【优化方案】
默认使用 **B. 强节奏悬念**，直接输出完整优化文，不要停下来等用户选择。只有用户明确说“给我几个方案”时，才先给出以下选项：
- **A. 保留原味**：只做轻润色与分段，最大限度保留原文的语气与节奏。
- **B. 强节奏悬念**：短句为主、信息前置，把反转与冲突尽量提前，适合快速抓人。
- **C. 情绪冲突**：强化对话与人物反应，把尴尬、冲突、反转的情绪张力写足。

【角色设定与变量】
  根据优化文拆出全部人物设定文字卡：发型、长相、年龄感、服装、配饰、体态，每个角色一段描述。
  女性角色统一基准：成年女性，7头身写实比例，鹅蛋脸，五官柔和精致，身形具有自然柔和的女性曲线，腰臀过渡柔和，肩背线条柔和不硬朗，体态舒展、不扁平、不男性化，比例协调真实，成熟轻性感、克制写实，不做夸张性感化处理。
  体态用温和、精准的写实描述，不要堆“丰满、性感、火辣”等夸张词；“扁平、男性肩宽、雌雄难辨”这类是负面约束，只能写进【负面提示词】，严禁混入画风的正面描述，否则会反向生成错误体型。
  需要轻性感时，用修身剪裁、柔和微开领口、浅锁骨小幅露肤等克制处理，禁止大面积露肤；【负面提示词】必须包含“过度暴露、低俗、色情”。

### 变量约定
1. 角色卡的 `name` 就是生图变量名，变量写法为 `{{角色名}}`，例如 `{{我}}`、`{{小八老师}}`、`{{朋友}}`。
2. 每页 `image_prompt` 中，凡是涉及角色外形、五官、发型、服装、配饰、身高体态的内容，一律只写变量，例如：
   - 正确：`人物严格遵循 {{我}}、{{小八老师}} 的角色设定与参考图。`
   - 错误：在提示词里重复粘贴“28岁、黑色短发、方圆脸……”等整段外形描述。
3. 完整外形描述保留在角色卡和每页 `character_review` 中；用户会在外部生图 AI 中把 `{{角色名}}` 绑定到对应角色参考图或角色设定。
4. **垫图优先声明**：每页 `image_prompt` 的【角色一致性】一行必须固定包含声明：`{{角色名}} 的外形以绑定的参考垫图为最高优先级，本提示词中的外形文字仅补充垫图无法呈现的细节，二者冲突时以垫图为准。` 这样用户更换垫图或在生图 AI 中微调设定后，无需修改任何分页脚本。
5. 设定变更闭环：用户在外部生图 AI 中确认的新设定（换装、换发型等）必须回填到工作台角色卡，角色卡是唯一事实源；剧情内单页换装只写进该页 `change_note` 与 `image_prompt`，不动角色卡。
6. 同一故事内角色卡姓名必须唯一且全程一致；分镜 `characters` 数组、`character_review`、`image_prompt` 中的变量名必须与角色卡姓名完全一致。
7. 如果某页出现了角色卡中没有的人物，先补充角色卡，再写该页；禁止使用未登记的角色变量。
8. 工作台不生成、不保存、不管理参考垫图，也不生成人物合影提示词。参考图由用户在外部生图 AI 中自行准备和绑定；不要停下来等待用户上传垫图。

【首图钩子规则】
第 1 页就是小红书作品的第一页，决定读者是否点进来，固定采用「提问互动开场」：
1. **主要旁白**：直接向读者发问，一句话、短促有力，制造代入感或认知缺口。
2. **副旁白**：交代情境（谁、在哪、发生了什么），让读者知道这个问题从何而来。
3. **信息差/悬念**：主要旁白或副旁白结尾要抛出反常信息、反转暗示或利益冲突，让读者想点进来看后续。
4. **画面**：聚焦核心人物或关键道具，通常用特写或中景；表情、动作、构图要为「问题」服务，而不是平铺直叙。
5. 第 1 页可以不按原文顺序起手，但必须与后文事实一致，不得编造原文没有的信息。
6. 第 2 页起进入正文，按优化文的自然顺序叙事；不要与第 1 页重复同一动作、同一句台词或同一画面。

【分镜拆页规则】
因为是整幅单画面不是分格漫画，一张图里塞不下太多内容，按以下规则拆页：
1. 每页主要旁白固定仅 1 句（情绪/钩子）；副旁白为本页优化后的故事内容，<50 个汉字，可 1–2 行；对话气泡不超过两个，单句尽量不超过 25 个字。对话必须来自优化文原文，可以截短，不得新增原文没有的台词；超长或超过两条时拆到相邻页，不得为了限制条数删掉关键台词。
2. 每页只表现一个动作或一个情绪点，不要一页塞多个情节。
3. 一段对话或一个情节内容多就拆成多页，换不同机位和景别来表现：全景交代环境、中景交代人物互动，特写交代表情和关键道具。机位方位的具体调度必须遵守【机位调度规则】。
4. 情绪高潮页用人物面部特写，转折页用全景，动作页用中景。
5. 为每页标注 `page_role`（页面作用），只能取：`钩子封面`（仅旧一次性流程使用）、`铺垫`、`冲突`、`反转`、`爆点`、`情绪高潮`、`收尾`。每页只选本页最主要的功能，不要全部笼统写「铺垫」：交代背景/人物=铺垫，矛盾开始激化=冲突，真相或人物态度翻转=反转，情绪或冲突最炸的一句=爆点，哭泣/争吵等情绪顶点=情绪高潮，收束结尾或引导互动=收尾。两步流程不生成钩子页：从本次选中段的第一段开始，按实际功能标注（通常为 `铺垫`），不要标 `钩子封面`。
6. 拆页时按故事自然节奏走，不要为了凑页数硬拆，也不要为了少出图把内容挤在一页里。
7. 称谓规则：第一人称主角统一用「我」，其他角色直呼姓名，禁用他/她代词。
8. 回忆页在副旁白开头标注「（回忆）」并交代时间或起因，同时把 `is_flashback` 写为 `true`。
9. 每页的人物外形、服装、配饰、体态必须与角色卡一致；换页不换人设，除非剧情明确要求换装。

【正文覆盖与去重规则】
拆页不是按「每页一个感觉」自由压缩，而是先保证优化文的每个信息点都有落页。违反以下任一条都必须先修分镜，再写回：
1. **先切 beat 再拆页**：把优化文按自然段/情节切成 beat 并编号（B1…Bn）；每个 beat 必须且只能落到一页。允许把相邻的极短 beat 合并到一页，但不允许跳过任何一个 beat。
2. **第 1 页钩子不计入覆盖**：第 1 页可以是提问互动开场，也可以复用开头信息；但正文仍要从优化文的第一个信息点开始完整覆盖，不能因为第 1 页写过就跳过该信息。
3. **预叙只拆一次，页序跟原文走**：如果优化文开头是后文的概述/预叙，不要把开头和后文各拆一遍。同一事件（同一场聚会、同一次重生、同一段对话）全篇只拆一次，选信息最完整的一处拆；开头独有的信息（决心清单、结论、反转钩子）单独成页或并入相邻页。**页序以优化文的章节/段落顺序为准，不得为了「更好读」自行重排**；如果原文本身是倒叙/预叙，保留它的顺序，并用「（闪前）」「（回忆）」或明确的时间句（如「直到十五年后」「十五年前」）把跳跃标清楚。
4. **非画面信息不许丢**：决心清单、心理活动、背景概述、时间跳跃等无法直接画出来的内容，必须用「内心独白页 / 道具特写 / 象征画面 / 人物特写」落页。`narration_sub` 保留原文关键信息，画面只负责氛围，不要求把清单每一项都画出来。
5. **副旁白保真**：`narration_sub` 以本页 `story_content` 为底稿，必须保留本页 beat 的事实、数字、时间、地点、姓名、关键物品和结果/情绪；只允许删语气词、重复词和纯过渡句，不得改写情节、不得合并信息点、不得把两段不同的事压成一句。画面文字可以 1–2 行，但不能只写半句让读者猜上下文。
6. **对话保真**：`dialogues` 优先使用优化文原话；可以截短，但不得新增原文没有的台词，不得把叙述改写成角色台词。关键台词超过单页上限时拆到相邻页，不能删除。
7. **拆完必须自检**：写回前输出「beat → 页码」覆盖表；再运行 `.claude/skills/story-breakdown/coverage_check.py`（或等价检查），确认：没有未落页的 beat、没有两页拆同一 beat、没有高度相似页、没有意外的大段倒序跳跃。发现问题先补页/删页/调页序，再进入【结果写回】。
8. **每页标注对应原文**：聊天输出每页时，在「本页故事内容」后标注 `本页对应：B<编号> / 原文第X段`，方便核对覆盖。
9. **连续阅读检查**：把所有页的 `narration_sub` 按页码顺序拼接，应当能读成一篇连贯的故事。读不通时先检查页序和过渡句，不要靠「本页故事内容」摘要来判断正文是否完整。

**字段职责**：`story_content`（本页故事内容）是给工作台看的清晰摘要，也是副旁白的底稿；`narration_main`（主要旁白）是画面上的情绪钩子；`narration_sub`（副旁白）是画面上的 1–2 行故事文字，必须在 50 个汉字内让读者看懂本页发生了什么。连续阅读、和优化文对照以 `narration_sub` 为准；写 `narration_sub` 前先看 `story_content`，不要直接从原文另写一版。

【机位调度规则】
景别（全景/中景/特写）只决定拍多近，机位方位决定从哪个方向拍。同一角度连拍多页是常见问题，必须主动调度：
1. 每页必须填写 `camera_angle`（机位方位），从以下词表中选取或组合（用「·」连接）：方位——正面平视、45°侧面、正侧面、背面、过肩视角；高度——俯视、仰视；特殊——主观视角（角色第一人称所见）。默认基准是正面平视，但整篇不允许全是正面平视。
2. **相邻两页禁止「机位方位 + 景别」完全相同**；同一场景的连续页，机位要有调度逻辑，不能原地不动。
3. 常用调度模板：
   - 双人对话场景：全景定位 → 甲过肩拍乙 → 乙过肩拍甲（正反打）→ 特写拍反应；
   - 情绪推进：中景 → 45°侧面 → 面部特写；
   - 转折/揭露页：切全景或俯视/仰视，用视角突变制造断裂感；
   - 回忆页：可用与主线不同的方位（如背面、俯视）拉开时空距离。
4. 机位变化必须服务叙事：展示环境用正面/侧面全景，强调压迫感用仰视，表现弱势或孤独用俯视，制造代入感用主观视角；不要为了变而变。
5. `image_prompt` 的【画面】一行必须写清机位方位（如「从主角背后过肩拍摄」「俯视角度」），生图 AI 才能执行。

【结果写回】
仅当指令提供了【故事 ID】时执行。接口地址默认 `http://127.0.0.1:8123`，以指令中给出的地址为准；所有请求体使用 UTF-8 编码的 JSON。

写回前先 GET `/api/stories/<ID>/breakdown` 确认当前状态：
- 返回 `null` 表示还没有拆解结果，本次 PATCH 会创建；
- 创建拆解要求故事有有效画风，否则接口返回 `422 ART_STYLE_REQUIRED`，此时告知用户先去故事列表重新选择画风并停止写回；
- 若已有旧结果，PATCH 会覆盖对应字段；开始写分镜前必须清空旧分镜页。

阶段 1：优化文与角色卡生成后，写入头部信息：

```json
PATCH /api/stories/<ID>/breakdown
{
  "optimized_content": "优化后的完整文章",
  "characters": [
    {"name": "我", "role": "主角", "appearance": "发型、长相、年龄感、服装、配饰、体态"}
  ]
}
```

说明：角色卡的 `name` 将作为 `{{角色名}}` 变量名，必须是稳定、唯一、可直接用于提示词的称呼。不要再写 `group_photo_prompt`。

阶段 2：清空旧分镜页，再逐页写入新分镜：

```text
DELETE /api/stories/<ID>/breakdown/pages
PUT    /api/stories/<ID>/breakdown/pages/<页码>
```

单页请求体字段与【每页输出格式】的对应关系：

| 请求字段 | 内容 |
|---|---|
| `is_flashback` | 是否回忆页，布尔值 |
| `page_role` | 页面作用：钩子封面 / 铺垫 / 冲突 / 反转 / 爆点 / 情绪高潮 / 收尾 |
| `story_content` | 本页故事内容 |
| `characters` | 出场人物姓名数组 |
| `character_review` | 人物设定回顾，写完整外形描述 |
| `scene` | 场景描述 |
| `action_state` | 动作与状态 |
| `change_note` | 变化说明 |
| `narration_main` | 主要旁白 |
| `narration_highlight` | 标红关键词；必须是本页主要旁白或副旁白中的连续片段，生图时内嵌在该句内标红，绝不单独成行 |
| `narration_sub` | 副旁白（1–2 行，<50 个汉字，标点不计） |
| `dialogues` | 对话气泡数组，最多 2 条，每条不超过 100 字，格式固定为 `说话人：台词`（说话人只用于定位气泡，不会写进画面） |
| `shot_type` | `全景` / `中景` / `特写` |
| `camera_angle` | 机位方位，如「正面平视」「过肩视角」「俯视·侧面」，不超过 50 字 |
| `image_prompt` | 完整生图提示词，角色外形用 `{{角色名}}` 变量 |

字段上限：页码 1～200；角色卡最多 20 张；`narration_main` 不超过 200 字；`narration_highlight` 不超过 100 字；`scene` / `action_state` / `change_note` / `narration_sub` 等长文本不超过 4000 字；`image_prompt` 不超过 8000 字。超出会导致 `422`，写回前需自行压缩，但不得缺项。

建议用一个 Python 脚本统一调用，避免长文本转义问题：

```bash
python3 - <<'PY'
import json, urllib.request

BASE = "http://127.0.0.1:8123"
STORY_ID = 2

def call(method, path, payload=None):
    data = None if payload is None else json.dumps(payload, ensure_ascii=False).encode("utf-8")
    req = urllib.request.Request(
        f"{BASE}{path}",
        data=data,
        headers={"Content-Type": "application/json"},
        method=method,
    )
```
